# Обновление и перезапуск

`.update` повторяет карточку исходного Updater: заголовок, branch и old → new, число коммитов/файлов,
добавленные/удалённые строки, относительная дата и UTC fallback. До 15 коммитов находятся в expandable quote,
остальное обозначается «…и ещё N». Длинные subjects сокращаются, HTML из Git не выполняется.

В первом ряду — зелёная «Обновить» и URL «Изменения», во втором — красная «Отмена».
В уведомлении вместо отмены — «Позже». Style/icon IDs сохранены; ссылки — на GitHub atarustia.
Пользовательские сообщения на Premium используют четыре emoji логотипа и custom emoji;
сообщения inline-бота сохраняют alt-текст. Дополнительной кнопки закрытия под этими экранами нет.

## Применение

1. Нажатие привязано к old/new SHA из показанной карточки. Поменявшийся HEAD или upstream требует нового просмотра.
2. Git получает origin и применяет **точный** fast-forward. Никаких reset, clean, rebase и скачивания executable.
3. `cargo build --locked --bin atarustia --target-dir ...` полностью собирает и линкует новый код, таймаут по умолчанию 1800 секунд.
   Два чередующихся build-каталога не дают Windows перезаписывать работающий exe.
4. Проверяется, что checkout всё ещё чистый и находится на одобренном commit.
5. Атомарно сохраняются сообщение, время старта, ожидаемая ревизия и список модулей; запрашивается штатный shutdown.
6. Сессии user/inline-ботов сохраняются. Процесс запускает уже собранный executable с прежними аргументами.
7. После ready hooks приходит итог с commit, временем, числом модулей и не загрузившимися именами.

Сборка и линковка завершаются до остановки аккаунтов. Это не гарантирует успешную работу нового кода
в Telegram; live-проверка остаётся отдельной. Обычный `.restart` запускает текущий executable без Cargo.
Release build не создаётся.

В прогрессе готовые шаги отмечены ✅ с временем, активный ⌛️, ожидающие ⚪️.
Ошибка зависимостей оставляет новый код на диске и старый процесс работающим, **не перезапускает** его.
«Ещё раз» повторяет Cargo только на той же ревизии. При недоступных кнопках повтори `.update`;
состояние retry хранится в БД. Сетевая ошибка редактирования прогресса сама по себе не меняет результат Git/Cargo.

## Вызовы

- `.update` — карточка с подтверждением. Без inline-бота — немедленное обновление, как в исходном модуле.
- `.update -f` — без карточки, но с теми же проверками dirty tree/SHA/fast-forward.
- `.update <40-char SHA>` — совместимый текстовый способ одобрить точный commit.
- `.restart` — подтверждение «Перезапуск / Отмена». Без inline-бота — сразу.
- `.restart -f` — сразу.

Отказ inline transport не трактуется как нажатие «Обновить»: выводится текстовая команда с SHA.
Команды и кнопки updater доступны только текущим владельцам, даже если command mask был расширен.
Кнопки содержат случайные tokens; после замены экрана прежние tokens недействительны.
Модули не могут поместить updater/restart действия в свои формы. Между аккаунтами действует общий maintenance lock.

## Уведомления и итог

Notifier стартует с задержкой 30 минут; требует подключённого inline-бота. Успешно отправленный SHA запоминается,
повторных уведомлений для него нет. «Позже» удаляет сообщение и не меняет checkout.
Карточка уведомления действует 24 часа; затем свежую можно запросить через `.update`.

`.config Updater` / `.fconfig Updater update_notifications false` управляют уведомлениями (default true).
Итог редактируется по сохранённому user/bot/inline reference с правильным DC для inline ID.
Если редактирование невозможно, итог отправляется в Избранное. Для не подключившегося бота есть fallback через 5 минут.
Персональные access hashes остаются только в локальном config; не выкладывай БД.

## Отличия от исходной реализации

### Сборка прервана по таймауту

Первая сборка в отдельном update target-каталоге может перекомпилировать все зависимости.
Прежний жёсткий дедлайн 300 секунд мог обрывать исправную сборку. Новый default — 30 минут;
окружение процесса/службы может задать `ATARUSTIA_BUILD_TIMEOUT_SECS=3600` (диапазон 60–86400).
Это абсолютный срок всей сборки, не таймаут бездействия. Вывод по обоим pipe ограничен
256 KiB на поток; ошибка дедлайна содержит последние 4000 символов stdout/stderr, время
и target-каталог. Отмена/таймаут прекращают группу процессов, а не оставляют Cargo/rustc
в фоне. Бот продолжает работать на прежнем бинарнике, исходники не откатываются, restart
после незавершённой сборки не выполняется.

Изменение переменной не исправляет уже запущенный старый бинарник с жёсткими 300 секундами.
Для выхода из этого состояния останови процесс/службу и выполни из checkout под тем же
пользователем `git pull --ff-only`, затем `cargo run --locked --bin atarustia` с прежними
аргументами запуска. У ручной сборки нет внутреннего дедлайна updater. Не запускай второй
экземпляр с той же Telegram-сессией. Для службы после сборки проверь, что ExecStart указывает
на собранный бинарник, а не на оставшийся старый executable в alternate target-каталоге.

### Cargo не найден (`os error 2`)

Updater ищет Cargo через явный абсолютный `CARGO`, абсолютные каталоги `PATH`,
`CARGO_HOME/bin`, `$HOME/.cargo/bin` / `%USERPROFILE%\.cargo\bin`, затем существующий
путь Cargo, записанный при сборке. Каталог checkout не используется как источник executable.
Папка выбранного Cargo добавляется в PATH только дочернего build-процесса, чтобы находился rustc.

У systemd пользователь/окружение могут отличаться от интерактивного терминала. Установи Rust
для пользователя службы либо задай в `/etc/atarustia.env` настоящий путь, например:

```ini
CARGO=/home/atarustia/.cargo/bin/cargo
```

Путь — пример, не универсальный. Не используй Cargo другого пользователя из закрытого `/root`:
`ProtectHome=true` может запрещать доступ. После изменения окружения перезапусти службу.
Если Cargo найден, но не запускается, проверь права, rustup/toolchain и окружение этой службы.
Ошибка отсутствующего checkout/Cargo.toml теперь выдаётся отдельно. Автоматический install toolchain
или сброс локальных изменений updater не выполняет.

Старый работающий executable не получает исправление, пока не обновлён из терминала:
при остановленном боте `git pull --ff-only`, затем `cargo run --locked` из checkout.
При local changes сначала разбери `git status --short`, не делай разрушительный reset.

- При переписанной истории updater не делает `reset --hard`: локальные коммиты остаются на месте.
- `uv sync` заменён Cargo с lockfile, а не обновлением зависимостей до произвольных последних версий.
- Ошибка inline UI не запускает обновление без подтверждения.
- Python-модули не загружаются; итог считает Rust SDK/JSON-Rhai модули и ядро.

Офлайн-тесты используют временный локальный Git remote, synthetic callbacks и отдельный ошибочный Cargo project.
Live update/перезапуск с Telegram, включая inline DC, пока требуют проверки на реальном аккаунте.
